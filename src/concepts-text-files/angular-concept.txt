/************************************************************************************************************
                                        AOT and JIT Compiler
 ***********************************************************************************************************
 -> Why Angular needs a compiler?
    In Angular, we writtes code in Typescript and Html, whereas the the browser does not understand typescript
    that's why Angular need a compiler to compile the code into JavaScript.

 -> Types of Compiler in Angular
    1. JIT : was default compiler till version 8
      - Compilation happens at the runtime in the Browser.
      - Compiler is included in the application bundle when send to the browser.
      - Load time is slow since compliler is included in the application bundle.
      - Bundle size is large since compiler included.
      - Security issue: more vulnerable to runtime Injection.

    2. AOT : Default compiler after version 9
      - Compilation happens during the build time/process 
      - Compiler is not included in the application bundle.
      - Fast Load time since compiler not included.
      - Small application bundle size.
      - More secure due to early validation.
*/


/************************************************************************************************************
                              COMPONENT RENDERING IN ANGULAR
 ***********************************************************************************************************
  -> In Angular, component rendering works by compiling HTML templates into JavaScript instructions (Ivy code) 
     that directly manipulate the DOM when application state changes.

  -> Lview(Logic view): A tree like data structure, Angular uses to keep track of the snapshot of component/DOM
                        and on re-rendering angular compare the current changes with the prev Lview tree to identify
                        the dom update.

  *** -> IVY in Angular: Angular compilation and rendering Engine designed to transform Typescript & Html code to JS.

  *** -> Tree Shaking: Tree shaking is the process of removing unused code from your final production bundle so 
                       users don't download dead scripts. Ivy makes this highly effective.                   

  1. Compilation Phase:

      -> AOT(Ahead of time) compiler perform the following task
          - reads the @component decorator, template markup and style.
          - the html template markup is converted into plain JavaScript instructions with the help of ivy instructions
          - the resulting code is structured into the "Create" and "Update" block on the UI

  2. Initial Render:
     - Instantiation
     - Creation pass - Ivy instructions
     - Logical View (Lview) Data structure created
     - Host element inserted into the dom       

  3. Change Detection and UI updates (Re-rendering)

      Phase Feature                         Default Strategy                         OnPush Strategy/Signals

      Trigger Mechanism           Monitored globally by Zone.js via
                                  browser macro/micro tasks.                         Directly flagged as dirty by reactive primitives or event firings.

      Traversal Path              Scans every component from root to 
                                  leaf on every tick.                                Skips stable subtrees entirely; only checks paths explicitly marked dirty.

      DOM Execution               Executes the Ivy "Update" block to 
                                  compare template state vs. current values.         Targets precise template bindings tied to changed data.                           
*/  


/************************************************************************************************************
                              CHANGE DETECTION IN ANGULAR
 ***********************************************************************************************************
 *** Historically, Angular relies on Zone.js, a library that monkeys-patches these asynchronous browser APIs 
     so Angular knows exactly when an event finishes and when it needs to scan the component tree.

  1. How Change Detection is Triggered
     - User Events: Button click, typing in a input etc
     - XMLHttpRequests: Fetching data from a backend API or server.
     - Timers: Asynchronous native browser API triggers like setTimeout() or setInterval()


  2. The Internal Detection Mechanics
     - [State Changes] ──> [Ivy Update Block Executes] ──> [Compare New Value vs. LView Cache] ──> [Direct DOM Patch]   

  3. Change Detection Strategies
     - You can configure how aggressively Angular checks your components by modifying the changeDetection property in 
       the @Component decorator.   

       Feature                         ChangeDetectionStrategy.Default                   ChangeDetectionStrategy.OnPush

   Component Scanning            Always checked during every single change          Skipped entirely unless explicitly marked                                                                                
                                 detection cycle across the app.                     as "dirty" or requiring a check

   Trigger Criteria             Any asynchronous event anywhere in the              Only when an @Input() reference changes, an event
                                application.                                        originates inside the component, or an async pipe emits.

   Performance Profile          Easy to develop, but becomes slow and heavy        Highly optimized; prevents unnecessary rendering across
                                in large scale applications.                       stable parts of the DOM.

  *** Note: Drawback of zone.js 
      - It was 3rd partiy library
      - On every re-render all the it was traversing through all the components from top to bottom. Time Comsuming and slow.
      - Bunder size was large

  4. The Signal-Based Future (Zone-less)
     - In modern Angular, Signals introduce a reactive primitive that shifts change detection from global tree-walking to granular, targeted updates.
     - No more ZoneJS
     - Producer/Consumer Relationship: When a Signal value shifts, it knows exactly which components read that specific Signal.
     - Targeted Notification: Instead of scanning from the top root down to find what changed, Angular can directly mark the exact component 
       containing the Signal as dirty and update it independently.                              
*/  


/***************************************************************************************************************
                                                DATA BINDING
****************************************************************************************************************
  -> Data Binding:- It is a way to bind the data (variables, array, object etc) defined your typescript code to 
    the your html template vice versa.

  -> There are 4 ways to acheive the data binding in Angular
    1. String interpolation: {{}}
    2. Property Binding    : [property]="data"
    3. Event Binding       : (event)="expression"    (expression = function)
    4. Two Way Binding     : [(ngModel)] = "data" 


  -> $event : $event is a special variable that captures and passes the event payload emitted by a DOM element 
              or a child component

   E.g. <input type="text" placeholder="Person name" (input)="onAddNewPerson($event)">
        <button (click)="clickMe($event)">Click Me</button>
         <form (submit)="onSubmit($event)">
            <input type="text" name="email">
            <button type="submit">Submit</button>
         </form>
        
 */

/*********************************************************************************************************************
                                         @ViewChild() decorator
**********************************************************************************************************************
 -> Used get a reference to the first matching element, component, or directive from within a component's (view). 

 -> This allows the parent component class(typescript file) to access and interact with the child's properties, methods, 
    or native DOM element directly.

 -> Access Timing (ngAfterViewInit): The queried element is not available immediately during the component's 
    construction or ngOnInit lifecycle hook. You must access it within the ngAfterViewInit lifecycle hook, which is 
    called after Angular has fully initialized the component's view.
*/





/*********************************************************************************************************************
                                         @ContentChild() decorator
**********************************************************************************************************************
 -> @ContentChild decorator (or the signal-based contentChild() function) is used to access the first matching element 
    or a component that has been projected into a component using content projection (the <ng-content> tag). 

 -> The property decorated with @ContentChild is initialized just before the ngAfterContentInit lifecycle hook, 
    so you must access it within or after this hook.
  
*/





/*********************************************************************************************************************
                                            VIEW ENCAPSULATION
**********************************************************************************************************************
 -> It is a mechanism that determines how the styles defined within a component are applied and how they interact with the 
    rest of the application's styles.

 -> It has 3 different options:-
    a) ViewEncapsulation.Emulated (Default) - Styles defined under the component doesn't affect the other component Styles
                                              but styles defined under the global styles will might still affect.
    b) ViewEncapsulation.ShadowDom - Style will only apply to the component itself - uses ture shadow dom technique

    c) ViewEncapsulation.None - No restriction any styles can be applied to any compoent's view 
*/

 /*********************************************************************************************************************
                                 @HostListener() and @HostBinding Decorator
**********************************************************************************************************************
 -> @HostListener: 
               - Allows us to subscribe to the event fired by the host element without writting the imperative
                 code in the constructor or using Renderer@.listen().

               - Whenever the specified event occures, the decorated method will be executed.

 -> @HostBinding:
              - Allows us to set the value of the property on the host element directly from your compoent or 
                directive class.

              - When the bound property of the class changes, Angular automatically updates the corresponding property
                on the host element during the change detection.

              - Ideal for dynamically updating the host element appearance for example applying a specific class, toggling 
                an attribute or setting a style.
